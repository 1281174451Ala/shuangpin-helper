# ADR 030：以公开仓库发布 v0.1.0 并隔离个人与公司 Git 身份

## 状态

已接受

## 背景

项目准备以 v0.1.0 版本首次推送到 GitHub 公开仓库。本地全部历史提交使用的是公司邮箱与真实姓名拼音（来自全局 Git 配置），直接推送会把公司邮箱暴露在公开的提交历史中。同时，日常仍在开发公司内项目，需要继续使用公司身份提交，两种身份必须互不干扰。

## 决策

1. **公开仓库**：仓库以 Public 形式发布，命名为 `shuangpin-helper`（小写 kebab-case，与 package.json/Cargo.toml 包名一致），并采用 MIT 许可证。
2. **身份改写**：推送前使用 `git filter-repo` 将全部历史提交的作者与提交者改写为 `Ala <91142503+1281174451Ala@users.noreply.github.com>`，使用 GitHub noreply 地址避免暴露任何真实邮箱。
3. **目录级身份隔离**：在全局 `~/.gitconfig` 中通过 `includeIf "gitdir:~/github_projects/"` 引入 `~/.gitconfig-personal`（个人身份）；该目录之外的仓库继续沿用全局的公司身份。前提是 `~/github_projects/` 下均为个人项目。
4. **本地目录不改名**：本地目录保持 `ShuangPinHelper`，仓库名与目录名允许不同。
5. **版本标记**：推送后打 `v0.1.0` 标签并创建 GitHub Release，附首个版本的功能清单。

## 影响

- 历史改写会变更所有提交哈希；因首次推送前执行，无远程与协作者，成本为零。此后如再需改写须 force push。
- 公司项目提交不受任何影响；个人项目目录下新建仓库自动使用个人身份，杜绝误用。
- GitHub 通过 noreply 邮箱自动将提交关联到个人账号，贡献统计可正常点亮。
- 公开发布意味着 README、docs/ 等内容对外可见，后续文档需保持对外部读者的可读性。
