# ADR 031：独立设置窗口与可持久化外观偏好

## 状态

已接受

## 背景

ADR 003 规定悬浮窗口不能接收编辑交互，ADR 013 也将主题与方案选择排除在 MVP 设置之外。现在需要提供方案、外观模式和空闲淡化配置，但不能让可编辑表单破坏用户在其他应用中的连续输入。

## 决策

从菜单栏或托盘打开可获得焦点、非置顶且具有普通标题栏的独立设置窗口；关闭时销毁，并在下次打开时重新创建。悬浮窗口继续保持非交互式。应用设置由 Rust 在应用配置目录的版本化 `settings.json` 中作为唯一来源原子持久化，前端通过 Tauri 命令读写并在成功或失败后同步运行时状态。

首版方案注册表只含小鹤双拼，设置页只读显示当前方案，同时持久化 `schemeId` 以预留扩展接口。外观模式为深色、浅色和持续跟随 macOS 系统三种完整内置主题；不允许逐项自定义状态颜色。空闲淡化提供“不淡化”或 1 至 30 秒延时，空闲透明度限制为 20% 至 100%（步长 5%）；默认值分别为跟随系统、3 秒和 30%。所有设置即时生效并持久化，不提供保存、取消或一键恢复全部默认设置。

写入失败时保留本次运行的预览并显示“下次启动将恢复旧设置”的错误。配置损坏或校验失败时，保留诊断副本、回退默认设置并继续启动；下次打开设置窗口时告知用户。位置、缩放、置顶和监听暂停不属于本次设置页范围。

## 影响

本 ADR 覆盖 ADR 013 中“方案固定且不提供主题配置”的范围限制，但不改变其余窗口设置的既有定义。实现须为设置模型、Rust 读写/迁移/损坏恢复、双窗口设置同步和 `prefers-color-scheme` 变化补充测试；还须将现有独立 `window-position.json` 的职责与新 `settings.json` 明确隔离，直至位置设置另行纳入统一模型。
