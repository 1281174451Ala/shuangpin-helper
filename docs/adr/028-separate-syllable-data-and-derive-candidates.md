# ADR 028：分离音节数据并派生候选索引

## 状态

已接受

## 背景

小鹤键位映射、普通话音节合法性和运行时第二键候选属于不同层次的数据。若把它们都写入 `shuangpin.json`，修改音节集合或切换双拼键位时容易产生重复和不一致。普通话合法音节也不能由声母与韵母的笛卡尔积直接确定。

## 决策

- `config/shuangpin.json` 只保存方案名称、版本、物理键到声母类别的 `initials` 映射，以及物理键到韵母的 `finals` 映射。
- 已审定的音节数据存放在独立的 `config/syllables-candidates.json`。它的 JSON 对象键是 `initials` 的唯一映射值，例如 `ch`、`sh`、`zh`；每个值是去重、按字典序排列的小鹤内部韵母记法数组。文件名保留以维持已有引用。
- `v`、`ve`、`van`、`vn` 分别表示 `ü`、`üe`、`üan`、`ün` 系列。`a`、`e`、`o`、`y`、`w` 是显式的零声母拼写类别。
- 配置加载后，将 JSON 对象转换为只读的 `Map<string, ReadonlySet<string>>`。运行时根据 `initials`、`finals`、`zeroInitials` 和正式音节数据派生“物理首键到合法第二键”的索引，不持久化该派生索引。
- `config/syllables-candidates.json` 的候选组合已完成审定，是运行时唯一的合法性数据来源；后续修改该文件时必须重新执行数据校验。

## 校验

- 每个 `initials` 的唯一映射值都必须在正式音节数据中恰好有一个非空条目。
- `zeroInitials` 的每项必须是音节数据中的键。
- 每个音节韵母必须至少能由一个 `finals` 键位表达。
- 每个数组必须去重并按固定字典序排列。

## 影响

音节合法性成为独立、已审定、版本化的静态内部数据。切换双拼键位时可复用声母类别和韵母集合；更新键位后只需重新派生候选索引。`syllables-candidates.json` 直接参与候选过滤，数据变更必须通过校验和测试。
