# MVP 实施设计

## 1. 目标与范围

本 MVP 是 macOS 上常驻的双拼学习辅助工具，而不是输入法。它在非交互式悬浮窗口中显示 26 个字母键的小鹤双拼映射，观察极少量全局按键事件，并高亮当前首键对应的合法第二键。

### 包含

- macOS、ANSI 美式 QWERTY 布局。
- 小鹤双拼的离线映射、无声调普通话音节表和零声母规则。
- 菜单栏常驻、悬浮键盘、最小设置、辅助功能权限引导。
- Rust 归一化按键事件，TypeScript 双拼状态机和候选计算。
- Tailwind CSS 实现 UI 样式，采用 utility-first 方法。

### 不包含

- 中文文本输入、拼音结果展示、按键历史或任何键盘事件持久化。
- 完整电脑键盘、按键按下动画、主题与状态颜色配置。
- 其他双拼方案、其他键盘布局、开机启动、练习模式和学习分析。

## 2. 模块边界

| 目录 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| `config/` | 小鹤键位映射、独立的合法音节数据、配置版本 | UI 逻辑、平台事件 |
| `src/engine/` | 加载和校验方案数据、候选查询、输入状态机 | React 渲染、macOS API |
| `src/components/` | 26 键虚拟键盘、键帽信息、设置界面 | 双拼规则判断、原生监听 |
| `src/store/` | UI 状态与持久化设置协调 | 拼音合法性规则 |
| `src-tauri/` | 菜单栏、窗口、辅助功能权限、全局监听、事件转发 | 候选计算与映射数据 |
| `tailwind.config.js` | Tailwind CSS 配置、内容路径、主题扩展 | 组件逻辑、业务规则 |
| `src/styles.css` | Tailwind 指令、全局基础样式 | 组件特定样式 |

## 3. 核心数据模型

建议先用 TypeScript 类型表达以下边界，再填充数据和实现。

### 3.1 方案数据

`config/shuangpin.json` 应包含：

- `version`：配置格式与内容版本。
- `name`：固定为小鹤双拼的方案标识。
- `initials`：字母键到声母的映射。
- `finals`：字母键到韵母的映射。
- `initials` 的值是与物理首键解耦的声母类别。
- `finals` 的值使用小鹤内部韵母记法；`v`、`ve`、`van`、`vn` 表示 `ü` 系列。

已审定的 `config/syllables-candidates.json` 包含：

- `zeroInitials`：零声母拼写类别，固定为 `a`、`e`、`o`、`y`、`w`。
- `syllables`：声母类别到合法韵母集合的 JSON 对象。键必须来自 `initials` 的唯一映射值，值为不含声调、去重且排序的小鹤内部韵母数组。

`config/syllables-candidates.json` 已完成审定，是运行时唯一的合法音节数据来源。文件名保留以维持已有引用；其中的 `syllables` 只能包含合法组合，可用于候选过滤。

启动时校验所有字段、所有键名、映射值和已审定音节集合。随后预先生成“第一键 -> 合法第二键集合”的索引，避免按键时遍历完整音节表。

### 3.2 原生事件协议

Rust 仅向前端发送如下归一化事件：

- `letter`：携带一个小写 `a` 至 `z`。
- `backspace`。
- `escape`。
- `space`。
- `enter`。

Rust 仅转发未按住 `Command`、`Control`、`Option` 或 `Shift` 的小写字母；大写字母、快捷键和其他按键均忽略。按键自动重复按接收顺序转发，不作过滤。不发送原始系统事件、修饰键、时间戳、窗口信息或其他按键内容。TypeScript 状态机以该协议作为唯一输入。

### 3.3 输入状态机

状态应保持为纯函数，可独立测试：

| 当前状态 | 事件 | 下个状态 | 界面效果 |
| --- | --- | --- | --- |
| 空闲 | 有效首键 | 等待第二键 | 仅高亮合法第二键，其余字母键灰化 |
| 等待第二键 | 任意字母键 | 空闲 | 立即重置，不显示已完成音节 |
| 等待第二键 | `Backspace` / `Escape` | 空闲 | 立即恢复默认状态 |
| 任意状态 | `Enter` | 空闲 | 立即恢复默认状态 |
| 任意状态 | 空格 | 状态不变 | 无视觉状态变化 |
| 任意状态 | 内部 `reset` | 空闲 | 清除过期候选 |

小鹤 MVP 的 26 个小写字母均是有效首键，因此不实现无效首键反馈；原因与其他方案的恢复条件见 ADR 029。监听暂停、权限撤销或原生监听器重启时，前端派发内部 `reset` 事件清除候选。等待第二键状态不设超时。状态机只保存必要的候选集合，不保存首键或完整输入历史。

## 4. 前端界面行为

### 4.1 虚拟键盘

- 仅渲染 26 个字母键，按照三行 QWERTY 排列。
- 默认宽度约 `420px`，用户可缩放到 `70%` 至 `160%`。
- 每个键帽常驻显示大写字母和对应的小鹤映射；无映射时仅显示字母。
- 固定三种状态：默认、候选、灰化。正常输入不播放按下动画。
- 有效首键后，不高亮第一键，不显示任何额外说明文本；用户只关注第二键候选。

### 4.2 设置与菜单栏

设置项仅包括：

- 窗口位置。
- 缩放。
- 透明度。
- 是否置顶。
- 是否暂停监听。

菜单栏至少提供：显示悬浮键盘、隐藏悬浮键盘、暂停/恢复监听、打开设置、退出应用。关闭悬浮窗口或设置窗口只隐藏窗口，只有菜单栏“退出”结束进程。

### 4.3 持久化与位置恢复

持久化最小设置并在下次启动恢复。若窗口的保存位置不在任何当前显示器工作区域，将其恢复到主显示器右下角；其他有效设置仍照常恢复。

### 4.4 样式实现

使用 Tailwind CSS 实现所有 UI 样式，遵循 utility-first 方法：

- 所有样式通过 Tailwind utility 类直接定义在组件 JSX 中。
- 全局基础样式（如字体、颜色、盒模型）定义在 `src/styles.css` 的 `@layer base` 中。
- 自定义颜色值使用 Tailwind 的任意值语法，如 `bg-[#27344c]`。
- 状态变体（如 `disabled:opacity-28`）直接在 utility 类中使用。
- 不维护自定义 CSS 类，所有样式通过 Tailwind 类组合实现。

## 5. 原生 macOS 行为

### 5.1 悬浮窗口

悬浮窗口应无边框、透明、默认置顶、忽略鼠标事件且不能获取键盘焦点。首次启动时显示该窗口。

### 5.2 权限与监听

获得辅助功能权限时，应用启动后立即监听。未授权时仍显示键盘和菜单栏，但停止监听；设置界面说明原因并提供打开系统设置的入口，不反复弹窗。

在应用回到前台、打开设置和用户手动点击“重新检测权限”时重新检查权限。权限恢复后，确保监听器只注册一次，再开始监听。

## 6. 建议实现顺序

1. 完成 `config/` 中的小鹤映射和音节数据，并先写数据校验测试。
2. 实现 `src/engine/` 的候选索引和状态机，覆盖正常声母、零声母和重置规则。
3. 完成仅含 26 个字母键的静态虚拟键盘，再接入状态机渲染。
4. 添加最小设置模型和持久化，处理窗口位置恢复。
5. 实现 Rust 侧菜单栏、窗口隐藏/显示和权限状态查询。
6. 接入原生监听与前端事件协议，最后在真实 macOS 上执行手动验收。

## 7. 实现完成条件

- 前端状态机能对每个受支持事件给出确定状态。
- 方案数据错误在开发/测试环境明确失败，正式环境禁用监听并提示配置无效。
- 悬浮窗口不抢占焦点、不拦截鼠标，菜单栏可恢复隐藏窗口并退出应用。
- 应用不存储、传输或显示已输入的文本内容，也不记录按键历史。
- 自动化测试和手动验收均通过 `test-and-acceptance-checklist.md` 的对应条目。
